# w10-cy1: Crop Management System (props, filter, two components)

## 1. What the question asks
- `src/App.js` holds `initialCrops` and renders `<CropDashboard initialCrops={...} />`.
- `src/Components/CropDashboard.jsx` (capital C folder): heading `CROP MANAGEMENT SYSTEM` (test is case-insensitive), label `Search by Crop Name:`, input placeholder `Search crops...`, search state, passes filtered list to `CropList`.
- `src/Components/CropList.jsx`: renders each crop name, type, status.
- Crops: Tomato, Apple, Wheat, Carrot, Banana (each with type and status).

## 2. What each test checks
Regexes, case-insensitive, `getByText` (must match exactly one element):
1. `/Crop Management System/i`
2. `/Search by Crop Name/i`
3. `/Tomato/i`, 4. `/Apple/i`
5. `getByPlaceholderText(/Search crops/i)`, change to `Tomato` -> Tomato present, `/Apple/i` absent
6. change to `Apple` -> Apple present, Tomato absent
7. change to `Carrot` -> Carrot present, `/Banana/i` absent

## 3. The original submission
Passes 7/7. Right: props flow App -> Dashboard -> List; `useState(initialCrops)` and `useState('')`; filter by `toLowerCase().includes`; `<label htmlFor>` + input id; `key` on list items; crop name in its own `<strong>`.
Fragile:
- Folder name `Components` vs import path must match case exactly (Linux is case-sensitive).
- Single-match rule: a crop name must appear in ONE element only. If status/type text contained "Apple" or "Tomato", `getByText` would throw. Also the heading must not contain a crop name.
- Keys by index (OK here, `name` would be better).

## 4. Common mistakes
- Import path casing (`./components/` vs `./Components/`).
- Not lifting the list down as props (`initialCrops`, `crops`).
- Filtering the original state in place (can't recover when the input is cleared).
- Label text different from `Search by Crop Name`.
- Rendering crop name twice (title + text) -> multiple matches.

## 5. Approach in 5 steps
1. In `App`, define the array and pass as prop.
2. In dashboard: `searchTerm` state, `filtered = crops.filter(...)`.
3. Render h1, label+input (controlled), `<CropList crops={filtered} />`.
4. In list: `crops.map` to a div with name + type + status, `key`.
5. Re-read test placeholders/labels and match them.
